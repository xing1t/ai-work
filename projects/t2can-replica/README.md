# T-3CAN PCB 复盘

2026-11-11。基于 LILYGO T-2CAN 普通版新增第三路 MCP2515，完成嘉立创 EDA PCB1。本文记录设计和检查过程中的失误，适用于下一次类似的原理图复刻和 PCB 布局。

## 这次最该改的两件事

### 1. 先把元件排整齐，再开始布线

我过早按焊盘能否放下判断布局。电阻电容没有按功能、方向和网格组织，部分封装的本体或固定脚挤到了相邻器件。布线后再移动器件，既要重走线，也要重新检查装配间距。后期检查消除了封装重叠，但仍有 13 对低于本项目 0.5 mm 的摆放目标，最小约 0.19 mm，位置在 L1/U1。[检查记录](#检查记录)

下次先固定板框、端子、USB、排针和开关等与外壳有关的器件，再按电源、主控、三路 CAN 分区。相同 CAN 通道复用一套单元布局，统一同组电阻电容方向、间距和位号。去耦、晶振、开关电源回路的距离服从电气要求。其余小件按主器件周边排成短行，密度过高时优先利用板内空白、适度扩大板框或把合适的低矮无源件翻到背面。

布局验收同时看本体、焊盘、固定脚、跨层通孔、丝印和插拔空间。本项目上限是 100 × 100 mm，0.5 mm 是摆放目标。低于目标的器件对逐项记录，布局和关键路径确认后再批量布线。用户手动调整过的位置作为新基线，按当前坐标继续工作。

### 2. 先做双层可行性验证，再决定升四层

我先撤了试铺铜，后续遇到扩展信号和电源走线拥堵时改成四层。当时缺少一个完整的双层布局与回流方案，也没有在升级前明确说明双层卡在哪里、四层能解决什么。四层版最终能通过 PCB 检查，双层能否满足这块板的要求没有验证。[检查记录](#检查记录)

下次在布局阶段就用双层方案试排。顶层优先布 USB、晶振、降压和 CAN 等关键路径，底层优先留连续 GND，并在换层处检查回流。先规划顶底铺铜边界和可用的接地过孔。关键走线、供电和隔离边界稳定后，再生成铜面、清孤岛、检查连通。测试时先做一小块，只重建选中的铜。若双层仍存在地被切碎、关键路径冲突、隔离净空不足或电源分配困难，再把具体冲突、尺寸和成本取舍列出来，决定是否升四层。 [嘉立创铺铜说明](https://prodocs.lceda.cn/cn/pcb/place-copper-region/)

## 其他返工与预防

| 本次发生的事 | 下次的做法 |
| --- | --- |
| PCB 已开始摆放时，USB-C 还没同步，后来又做了封装匹配、板边和定位孔复核。 | 原理图转 PCB 前按位号比对原理图、PCB 和明确不装的器件。USB-C、端子、天线接口和安装孔优先核对实物、封装、针序和装配边界。缺件要区分是库封装缺失、导入遗漏还是计划不装。 |
| 局部原理图使用标签过多，关系难读。 | 去耦、上拉和周边元件围绕主器件直接连线。同一功能块内画出电源支路和回路，跨页或长距离信号再用标签。 |
| 先铺铜时还有大量飞线，整面试铺又新增 103 项自由铜报错。 | 先接信号和供电，再做受控铺铜。主控 GND 与每路 CAN 的隔离地按网和区域分开。绕开降压开关区，检查 USB 差分线旁的铜间距。按铜面是否实际连到 GND 过孔或焊盘判断孤岛。撤销时同时核对铺铜边界和生成的铜对象，复查 DRC。 |
| U3 在板内，我起初笼统说要给“天线附近”禁铺，引起了对内层地铜的误解。 | 先核对料号。WROOM-1U 用外接天线，检查同轴线的走向和天线本体的净空。用板载天线的模块则按对应厂家图纸做板边布局和禁铺。 [乐鑫模块数据手册](https://documentation.espressif.com/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf#page=46) |
| 串口和扩展插座移位后，画面上似乎接触的末段仍报未连接。精确重接、补接地过孔并重新打开 PCB 后，接口报错清除。 | 先读每个焊盘的坐标、层、网名和实际铜形，再修末段。表层贴片地要有明确的换层路径。几何已接触而报错仍在时，保存后重开并复查，再决定是否继续改铜。 |
| USB-C 封装自带板边参考线，重新打开文档后曾回到板框层。 | 交付前从 Gerber 看板框和钻孔，检查板框是否闭合、有没有多余轮廓、USB 定位孔有没有误当成安装孔。移动接口或重开后重新核对导出。 |

## 怎么少花 token

1. **保留一份当前状态。** 一页记板尺寸、叠层、元件数量、当前阶段、未决项和最近证据。每阶段更新一次，续做时只读这一页与本阶段的回读。
2. **让本地脚本筛差异。** 对比位号、封装、坐标、网络和 DRC 类型，只输出变化数量与少量异常。全量网表、铜形和 JSON 留在本地。工程规则、官方图纸和 API 只查当前动作相关的条款。
3. **按功能块批处理。** 三路同类 CAN 复用布局和检查方式。对同一批先做离线校验，再核对连接、工程和活动页。小批写入、回读、保存，检查上一批结果后再推进。
4. **同一报错复现就换诊断方式。** 先核实目标、图元坐标和网络，再用单点试改、保存重开或独立几何检查区分真实断点和编辑器状态。桥接超时先回读是否已经生效，避免重复生成器件或走线。
5. **用检查结果推进交接。** 阶段结束只报改了什么、通过了什么、还缺什么。只有外壳孔位、接口针序或必须更改板尺寸和叠层等会改变结果的事项才集中向用户确认。token 优化针对重复上下文、全量回包和盲目重试，保留关键校验。
